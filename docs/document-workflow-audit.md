## Documents modules after the cleanup

Patients and doctors keep a Documents entry as an index of their role-relevant forms and records. It has no personal/private file upload area.

Patient Documents links to registration, baseline self-report, care permissions, agreement information and released summaries. The clinical baseline link is gated until approval.

Doctor Documents links to assigned visits for digital consultation notes and assessments. Approved doctors can download the existing welcome pack. Pending doctors see the approval requirement instead of a download or clinical form link.

Admin Documents retains its submitted-record index and the previously approved admin-only private-file tab. The generic GET/POST /files library now requires an approved administrator. Existing stored files are not deleted; the download endpoint retains owner checks for legacy links.

The index does not claim that digital records are downloadable PDFs. Patient consent copies, executed agreements, consultation exports and other approved outputs need their own defined export/release workflows.

## How to handle any newly required upload

For each replacement file, record its purpose, completing role, required fields and whether the information already exists as a digital form. Add an upload only when an actual supporting file is needed, such as a specified credential or an externally signed document.

A required upload should be tied to a named requirement and submission record, with patient/doctor ownership, explicit admin review access, submission time, version/replacement history and status. Returned documents should be available to the intended user for download and correction when appropriate. Administrator private storage is not a substitute for that workflow.

This supporting-file submission/review workflow is not yet implemented. The revised source documents will determine which specific requirements it needs.
